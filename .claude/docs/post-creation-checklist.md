## 为什么需要审查清单

### 审查的价值

1. **发现问题**：初稿往往存在简化、模糊、遗漏等问题
2. **提升质量**：系统化检查比随机检查更全面
3. **节省时间**：一次性批量修复，而非反复修改
4. **建立标准**：形成可复用的质量标准

### 不审查的风险

- ❌ 核心概念过于简化，读者不理解
- ❌ 技术术语未通俗化，受众面窄
- ❌ 图片遗漏或位置不当
- ❌ 工具说明缺失，可信度低
- ❌ 风格不统一，专业度受损

---

## 审查时机

### 推荐审查点

| 时机 | 审查内容 | 耗时 |
|------|---------|------|
| **初稿完成后** | 全面审查（本清单全部） | 15-30分钟 |
| **发布前1小时** | 快速检查（P0+P1项） | 5-10分钟 |
| **发布后收到反馈** | 针对性修复 | 视情况而定 |

### 审查流程

```
初稿完成
    ↓
【全面审查】（使用本清单）
    ↓
修复问题
    ↓
【快速检查】（P0+P1）
    ↓
发布
```

## 完整审查清单

### 一、核心概念审查 (P0 - 必须修复)

#### ✅ 简化概念检测

**检查项**：
- [ ] 是否有过于简化的段落？（如：只有公式/列表，无解释）
- [ ] 技术术语是否有通俗解释？
- [ ] 读者能否在不查资料的情况下理解？

**如何检测**：
1. 搜索"### "（章节标题）
2. 检查每个章节的字数
3. 如果章节<200字，可能过于简化

**示例问题**：
```
### 3. 成功公式
成功 = 能动性 × 机会 × 智力
其中智力 = 行动 → 感知 → 比较 → 调整
```
→ **问题**：只有公式，无解释

**修复方法**：
```
### 3. 成功公式

Daniel Koe 给出了一个简洁的成功公式：

```
成功 = 能动性 × 机会 × 智力
```

**这是什么意思？**

- **能动性**：你主动采取行动的能力...
- **机会**：你遇到的可能性...
- **智力**：这里不是IQ测试的分数，而是...

**智力的4步循环**：
行动 → 感知结果 → 与目标比较 → 调整行为 → 再次行动...
```

---

#### ✅ 术语通俗化检测

**检查项**：
- [ ] 专业术语是否第一次出现时有解释？
- [ ] 是否能用大白话重述核心概念？

**如何检测**：
1. 标记所有专业术语（如"身份""反愿景""能动性"）
2. 检查是否有定义或类比

**示例问题**：
```
"改变身份才能改变行为"
```
→ **问题**："身份"对普通人来说很抽象

**修复方法**：
```
"改行为没用，得先改变'你怎么看自己'。"

比如：
- 不是"我逼自己每天早起"
- 而是"我是一个早起的人"
```

### 二、结构与逻辑审查 (P0 - 必须修复)

#### ✅ 段落过渡检测

**检查项**：
- [ ] 段落之间是否有逻辑连接？
- [ ] 是否有突兀的跳跃？

**如何检测**：
1. 阅读每段的最后一句和下一段的第一句
2. 检查是否有承上启下

**修复方法**：
- 添加过渡句："接下来..."
- 使用承上启下的表达："基于前面..."

---

#### ✅ 逻辑完整性检测

**检查项**：
- [ ] 论点是否有论据支持？
- [ ] 是否有虎头蛇尾的情况？

**如何检测**：
1. 检查每个论点
2. 确认都有例子、数据或引用

---

### 三、内容完整性审查 (P1 - 强烈建议)

#### ✅ 图片标记检测

**检查项**：
- [ ] 是否每500字有一张图片？（长文）
- [ ] 图片标记是否完整？（描述+位置+prompt）
- [ ] 图片位置是否合理？

**如何检测**：
```bash

# 统计字数

```

**参考密度**：
| 文章字数 | 推荐图片数 |
|---------|-----------|
| 2000字 | 2-4张 |
| 5000字 | 8-10张 |
| 8000字 | 12-15张 |

### 四、语言风格审查 (P1 - 强烈建议)

## 常见问题修复指南

### 问题1：核心概念过于简化

**症状**：
- 章节只有公式/列表，无解释
- 字数<200字

**修复步骤**：
1. 添加"这是什么意思？"部分
2. 用类比/例子解释
3. 说明"为什么重要"

**模板**：
```markdown
### X. 概念名称

**公式/定义**：
```
...
```

**这是什么意思？**

- **要素A**：通俗解释...
- **要素B**：通俗解释...

**为什么重要？**

因为...
```

---

### 问题2：术语过于抽象

**症状**：
- 读者需要反复思考才能理解
- 无法用大白话重述

**修复步骤**：
1. 用"不是...而是..."重新表达
2. 提供具体例子
3. 用生活场景类比

**模板**：
```markdown
**术语**：专业说法

**通俗版**：大白话解释

**举例**：
- 术语：我要每天早起
- 通俗版：我是一个早起的人
```

---

### 问题3：图片遗漏

**症状**：
- 长文（5000+字）图片<5张
- 密集文字段超过800字

**修复步骤**：
1. 统计字数和图片数
2. 计算图片密度（应~500字/张）
3. 在密集段落添加图片标记

**工具**：
```bash
# 统计图片数
grep -c "📷" content.md

# 统计字数
wc -m content.md

# 计算密度
图片数 = 字数 / 500
```

---

### 问题4：过渡不自然

**症状**：
- 段落间跳跃
- 读者感到突兀

**修复步骤**：
1. 识别跳跃点
2. 添加过渡句

**过渡句模板**：
- "接下来，我们来看..."
- "基于前面的..."
- "不仅如此，还有..."
- "但是，问题来了..."

---

### 问题5：工具说明缺失

**症状**：
- 文章提到使用工具，但无说明
- 读者不知道如何复刻

**修复步骤**：
1. 选择合适位置（方法论说明后/相关资源）
2. 添加三部分：工具组合、为什么有效、其他选择

**模板**：
```markdown
### 关于使用的工具

**我使用的工具组合**：
1. **工具A**：特点+适用场景
2. **工具B**：特点+适用场景

**为什么这个组合有效？**
- 原因1
- 原因2

**如果你想复刻这个过程**：
- ✅ 推荐工具
- ❌ 避免工具
```

## 总结

### 审查流程

```
初稿完成
    ↓
【P0检查】→ 修复 → 【P1检查】→ 修复 → 【P2检查】→ 优化
    ↓
发布前5分钟快速检查
    ↓
发布
```

### 核心原则

1. **读者视角**：想象第一次阅读的人，能理解吗？
2. **测试驱动**：用"16岁学生测试"检验通俗化
3. **渐进修复**：先P0，再P1，最后P2
4. **快速迭代**：不要追求完美，追求够用

---

**记住**：
> **好的审查 = 系统化检查 + 读者视角 + 优先级明确**
