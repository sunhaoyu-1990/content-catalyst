# 改进路线图

**用途**: 本文档记录系统的改进计划和技术债务。

---

## 优先级定义（P0/P1/P2）

| 优先级 | 定义 | 响应时间 | 示例 |
|--------|------|---------|------|
| **P0** | 阻碍用户采用或系统无法正常使用 | 立即修复（24小时内） | 新用户无法开始第一次创作 |
| **P1** | 影响用户体验或效率，但有可用方案 | 下一版本（1-2周内） | 索引需要手动维护 |
| **P2** | 优化提升或长期改进 | 未来考虑（1-3个月内） | 自动化索引 |

### 2. Windows 路径检查清单

**创建前检查**：
- [ ] 主题名称 ≤ 30 字符
- [ ] 完整路径长度估算 ≤ 200 字符（留60字符余量）
- [ ] 避免使用特殊字符：`< > : " | ? *`
- [ ] 使用连字符 `-` 代替空格

**创建后验证**：
```bash
# 在 Git Bash 或 PowerShell 中运行
echo "${#your-path}"  # 显示路径长度，应 ≤ 260
```

**路径长度优化策略**：
- 缩短主题名称（使用缩写或拼音）
- 减少嵌套层级（考虑使用更扁平的结构）
- 将项目放在靠近根目录的位置

## 技术债务清单

| 债务项 | 影响 | 优先级 | 偿还计划 |
|--------|------|--------|----------|
| 手动维护索引 | 数据一致性风险 | P1 | P2: 开发索引自动化脚本 |
| 评分权重重复定义 | 维护成本 | P2 | P1: 建立单一数据源 |
| 缺少自动化测试 | 质量保证风险 | P2 | P2: 实现测试套件 |
| 文档与代码同步 | 过时风险 | P1 | P1: 建立更新触发器 |
| 版本管理逻辑未集成 | 功能不完整 | P1 | P1: 集成到各技能 |

### 债务详情

#### 1. 手动维护索引

**问题描述**：workspace/index.md 和 talk_with_ai/index.md 需要手动更新

**当前方案**：最佳努力维护策略
- 创建任务时必须更新
- 完成任务时更新状态
- 定期整理（每周）

**未来方案**（P2）：自动化脚本
- 监控目录变化
- 自动生成索引
- 提供手动确认接口

**理由**：自动化会增加复杂度，当前手动方案已足够

#### 2. 评分权重重复定义

**问题描述**：评分权重在多处定义
- `scoring-weights.md` 文件
- `CLAUDE.md` 平台配置
- 各技能文件中

**当前方案**：多处定义，手动同步

**未来方案**（P1）：单一数据源
- 创建 `scoring-weights.json` 作为唯一数据源
- 各技能和文档从 JSON 读取
- 修改一处，全局更新

#### 3. 缺少自动化测试

**问题描述**：技能文件和目录结构没有自动化测试

**风险**：修改可能破坏现有功能

**未来方案**（P2）：测试套件
- 验证目录结构正确性
- 验证技能文件完整性
- 验证评分权重一致性

#### 4. 文档与代码同步

**问题描述**：文档和技能代码可能不同步

**当前方案**：人工检查和更新

**未来方案**（P1）：更新触发器
- 技能文件修改时提醒更新文档
- 定期运行一致性检查
- 在文档中标注最后验证日期

#### 5. 版本管理逻辑未集成

**问题描述**：版本管理规则（日期、v2、v3）未在技能中实现

**影响**：用户需要手动创建版本目录

**未来方案**（P1）：技能集成
- 检测是否已有版本目录
- 自动判断使用日期还是 v2
- 自动创建目录结构

## P2 未来改进

### 1. 索引自动化

**功能**：
- 监控 workspace/ 和 talk_with_ai/ 目录
- 自动检测新增和修改
- 生成/更新 index.md
- 提供预览和确认接口

**技术方案**：
- Python 监控脚本（watchdog）
- Markdown 生成（jinja2 模板）
- 定时任务（cron/schedule）

### 2. 单一数据源

**功能**：
- 创建 `config/scoring-weights.json`
- 技能文件从 JSON 读取权重
- 文档自动生成平台配置章节

**数据结构**：
```json
{
  "platforms": {
    "zhihu": {
      "name": "知乎",
      "weights": {
        "专业性": 4,
        "可信度": 3,
        "热度": 2,
        "相关性": 1
      },
      "threshold": 7
    }
  }
}
```

### 3. 技能实现检查清单

**检查项**：
- [ ] workspace 目录创建逻辑
- [ ] 版本管理逻辑（日期 → v2 → v3）
- [ ] 索引更新提醒
- [ ] 文件编码验证（UTF-8 without BOM）
- [ ] Windows 路径长度检查

### 4. 高级定制功能

**功能**：
- 自定义评分权重
- 自定义目录结构
- 自定义版本命名规则
- 自定义索引模板

**实现**：
- 配置文件 `config/user-settings.json`
- 技能读取配置并应用
- 提供默认值和验证

## 优先级判断标准

**如何判断优先级**：

1. **P0 - 立即修复**
   - 新用户无法使用核心功能
   - 系统完全无法工作
   - 数据丢失风险

2. **P1 - 下一版本**
   - 影响用户体验但有变通方案
   - 维护成本显著增加
   - 功能不完整但可用

3. **P2 - 未来考虑**
   - 优化提升性质
   - 自动化程度提升
   - 长期架构改进
