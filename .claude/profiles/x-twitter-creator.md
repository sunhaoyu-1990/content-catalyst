## 内容创作规范

### 内容类型偏好

**✅ 推荐主题**：
- 观点表达（独特见解、行业评论）
- 资讯分享（最新动态、重要新闻）
- 经验总结（一句话tips、踩坑记录）
- 工具推荐（简洁介绍、核心价值）
- 讨论发起（开放问题、征集意见）

**❌ 避免主题**：
- 过长的教程（不适合碎片化阅读）
- 敏感话题争议
- 纯广告推广
- 连续刷屏

### 内容格式标准

**推文（Post）**：
```
长度: 1-3句话（<280字符）
要素: 观点+价值+互动引导
```

**推文示例**：
```
刚刚发现一个超好用的性能分析工具perf，一行命令就能定位CPU热点！
行命令→火焰图→找到瓶颈函数，排查时间从2天缩短到2小时。
#技术工具 #性能优化
```

**线程（Thread）**：
```
结构: 1条主推文 + 3-10条后续推文
用途: 深度阐述、教程分享、案例分析
```

**线程结构**：
```
推文1: 吸引眼球的主观点（钩子）
推文2: 背景介绍
推文3-N: 核心内容（分点阐述）
推文N+1: 总结+行动号召
```

**回复（Reply）**：
```
长度: 1-2句话
语气: 建设性、专业、友好
目的: 补充说明、提出问题、表达认同
```

### 语言风格要求

**语气特点**：
- ✅ 简洁有力（每句话都有价值）
- ✅ 观点鲜明（不模棱两可）
- ✅ 易于传播（可转发、可引用）
- ✅ 专业但不刻板

**语言特征**：
- 短句为主（1-2句话）
- 关键词前置
- 适当使用缩写
- emoji适度使用

**简洁技巧**：
- 去除冗余词汇
- 使用符号增强表达（→、>、+）
- 数字具体化
- 重点用粗体（如适用）

**示例对比**：
```
❌ 冗长: "我认为在软件开发过程中，选择合适的工具对于提高团队效率是非常重要的，因为..."

✅ 简洁: "工具选对，效率翻倍。我们团队从2天排查→2小时定位问题。"
```

## 格式规范

### 推文规范

**长度**: 建议<280字符（硬限制）

**结构**：
```
[观点/发现] + [简短说明] + [价值/效果] + [可选：链接/标签]
```

**示例**：
```
用了1周perf，终于定位到那个CPU 100%的问题。
原来是memcpy在CPU和GPU间频繁拷贝数据。
优化：改为GPU全流程处理，CPU占用从100%→40%。
#性能优化 #Linux
```

### 线程规范

**主推文（推文1）**：
- 吸引眼球的钩子
- 核心观点概括
- 引导阅读后续内容

**后续推文**：
- 每条推文2-3句话
- 逻辑连贯、逐步展开
- 最后一条总结+行动号召

**线程示例**：
```
1/8 从2天排查→2小时定位，我们用perf解决了性能问题。

2/8 之前：CPU 100%，不知道哪里卡。传统方法：加日志、猜测、反复调试。

3/8 解决方案：使用perf（Linux原生工具）。

4/8 一行命令：
perf record -F 99 -p <PID> -g -- sleep 60

5/8 生成火焰图：
perf script | flamegraph.pl > cpu.svg

6/8 发现：memcpy占用30% CPU时间！

7/8 优化：改为GPU全流程处理，数据不下显存。

8/8 效果：CPU占用100%→40%，排查时间2天→2小时。

工具链接：[链接]
#性能优化 #Linux工具
```

### 标签规范

**使用原则**：
- 1-3个标签为宜
- 选择相关性强的话题
- 优先使用热门标签
- 避免过度使用

**常用标签**：
```
#技术 #编程 #性能优化 #架构设计
#AI #机器学习 #DevOps #工具推荐
#职场 #成长 #创业 #行业洞察
```

## 常见问题

### Q1: 推文写多长合适？
**A**:
- 最优：100-200字符
- 上限：280字符（硬限制）
- 原则：能短则短，每句话都有价值

### Q2: 什么时候发推文效果最好？
**A**:
- 工作日：上午9-10点，下午2-3点
- 周末：上午10-11点
- 避开：深夜、凌晨、节假日

### Q3: 如何提高互动？
**A**:
- 提出开放性问题
- 及时回复评论
- 参与热门话题讨论
- @相关人士或公司
- 定期发布有价值的内容

### Q4: 线程和单条推文怎么选择？
**A**:
- **单条推文**：快速分享、一句话tips、观点表达
- **线程**：教程分享、深度分析、案例研究
