# 内容创作后审查清单

**版本**: v1.0
**触发条件**: 文章初稿完成后（`workspace/.../02_create/{platform}/article.md`存在）

---

## 规则目的

确保所有产出的文章内容经过质量审查，符合发布标准。

## 触发时机

**当检测到以下情况时，自动触发本审查**：
- `workspace/.../02_create/{platform}/article.md` 文件存在
- 文件内容长度 > 1000 字
- 用户表示"初稿完成"或类似表述

## Profile规范加载

**审查前首先加载相关Profile规范**：

### Step 1: 确定平台
- 从文件路径识别平台：`{platform}` (zhihu, xiaohongshu, linkedin, x-twitter)

### Step 2: 加载Profile规范
```
加载基础规范：
  Read profiles/content-creator-common.md

加载平台特定规范：
  如果是 zhihu → Read profiles/zhihu-creator.md
  如果是 xiaohongshu → Read profiles/xiaohongshu-creator.md
  如果是 linkedin → Read profiles/linkedin-creator.md
  如果是 x-twitter → Read profiles/x-twitter-creator.md
```

### Step 3: 应用Profile检查
审查时必须检查内容是否符合：
- ✅ Profile的核心原则
- ✅ Profile的内容质量标准
- ✅ Profile的格式规范
- ✅ Profile的语言风格要求

## 必须审查项

### 1. 事实准确性 ✅
- [ ] 所有数据可验证（有来源标注）
- [ ] 产品功能、命令、工具名称准确
- [ ] 案例真实可信
- [ ] 无杜撰内容

### 2. 逻辑一致性 ✅
- [ ] 前后论述不矛盾
- [ ] 因果关系合理
- [ ] 论证逻辑清晰

### 3. 语言质量 ✅
- [ ] 符合中文表达习惯
- [ ] 无语法错误
- [ ] 专业术语使用准确
- [ ] 段落长度适中

### 4. 平台适配 ✅
- [ ] 符合平台内容类型（知乎专业/领英商业/小红书种草）
- [ ] 字数符合平台要求
- [ ] 话题标签完整
- [ ] 格式符合平台规范

### 5. 结构完整性 ✅
- [ ] 有吸引人的标题
- [ ] 有明确的引言/前言
- [ ] 主体内容完整
- [ ] 有总结或行动号召

### 6. 原创性 ✅
- [ ] 引用内容注明来源
- [ ] 参考资料重新组织表达
- [ ] 原创观点有独立思考

## 审查流程

```
文章初稿完成
    ↓
运行本审查清单（6个维度）
    ↓
发现问题？
    ├─ 是 → 标记问题 → 修改 → 重新审查
    └─ 否 → 通过 → 触发图片标记步骤
```

## 常见问题类型

| 类型 | 示例 | 修复方法 |
|------|------|---------|
| 事实错误 | 杜撰的工具功能 | 查阅官方文档修正 |
| 逻辑矛盾 | 前后结论不一致 | 调整论述逻辑 |
| 语言生硬 | 翻译腔严重 | 改写为自然中文 |
| 平台不符 | 知乎文章太口语化 | 调整语言风格 |
| 结构缺失 | 缺少总结 | 添加总结段落 |

## 审查输出格式

**在文章末尾添加审查结果块**（审查完成后删除）：

```markdown
> **创作后审查结果**
> - 事实准确性：✅ 通过
> - 逻辑一致性：✅ 通过
> - 语言质量：✅ 通过
> - 平台适配：✅ 通过
> - 结构完整性：✅ 通过
> - 原创性：✅ 通过
>
> **审查时间**：YYYY-MM-DD
> **审查状态**：通过 → 可进入图片标记阶段
```

## 不通过的处理

**如果任一审查项不通过**：
1. 在文中标记问题位置（使用 `<!-- ISSUE: 问题描述 -->`）
2. 提供修复建议
3. 修改后重新审查该选项
4. 直到所有项通过

## 自动触发下一阶段

**审查全部通过后**：
- 自动触发 `content-image-marking.md` rule
- 开始为文章添加图片标记

---

**重要说明**：
1. 本rule在完整模式和极简模式下都会触发
2. 审查必须在图片标记之前完成
3. 审查不通过的内容不应进入发布准备阶段
