# 技术架构详解

**用途**: 本文档详细说明系统的技术实现和架构设计。

## 模块化技能架构

### 目录结构

```
.claude/skills/
├── _shared/                    # 共享核心逻辑（基类）
│   ├── collect-base.md         # 4轮搜索策略核心逻辑
│   ├── create-base.md          # Onboarding + 本地资料整合
│   ├── filter-base.md          # 10分评分系统核心逻辑
│   └── publish-base.md         # Playwright自动化核心逻辑
│
├── x-                          # X (Twitter) 平台技能
│   ├── x-collect.md            # 继承 collect-base
│   ├── x-create.md             # 继承 create-base
│   ├── x-filter.md             # 继承 filter-base
│   ├── x-publish.md            # 继承 publish-base
│   └── references/             # 平台特定配置
│       ├── post-patterns.md    # 内容类型模式
│       └── scoring-weights.md  # 评分权重
│
├── zhihu-                      # 知乎平台技能
│   └── ... (结构同 x-)
│
├── xiaohongshu-                # 小红书平台技能
│   └── ... (结构同 x-)
│
└── linkedin-                   # 领英平台技能
    └── ... (结构同 x-)
```

### 继承模式

**声明方式**：
```markdown
继承: ../_shared/collect-base.md
```

**继承关系**：
```
_shared/collect-base.md (基类)
    ↑ 继承
    │
    ├─ x-collect.md (添加 X 特定搜索关键词)
    ├─ zhihu-collect.md (添加知乎特定搜索关键词)
    ├─ xiaohongshu-collect.md (添加小红书特定搜索关键词)
    └─ linkedin-collect.md (添加领英特定搜索关键词)
```

### 为什么这样设计？

1. **避免代码重复**：
   - 4个平台 × 4个技能 = 16个文件
   - 如果不用继承，每个文件都要复制核心逻辑
   - 修改一处需要改 16 个文件

2. **统一核心逻辑**：
   - 修改基类文件，所有平台自动更新
   - 确保 4 轮搜索策略一致
   - 确保 Onboarding 流程一致

3. **便于扩展**：
   - 添加新平台时，只需继承基类
   - 配置平台特定参数即可
   - 无需重复实现核心逻辑

## 关键技术决策

### 1. 双层 Onboarding

**问题**：AskUserQuestion 工具限制一次最多 4 个问题

**解决方案**：双层提问
- **Layer 1**: 共享问题（3个）- 使用场景、内容领域、语言风格
- **Layer 2**: 平台特定问题（2-3个）- 目标受众、内容形式等

**代码示例**：
```markdown
## create-base.md

### Layer 1: 共享问题
使用 AskUserQuestion 询问 3 个共享问题

### Layer 2: 平台特定问题
{% if platform == 'zhihu' %}
  询问知乎特定问题
{% elif platform == 'xiaohongshu' %}
  询问小红书特定问题
{% endif %}
```

**为什么这样设计**：
- 适配工具限制（4个问题）
- 收集完整信息（5-6个问题）
- 用户体验流畅（分两次提问不突兀）

### 2. 平台差异化评分

**设计**：
| 平台 | 评分公式 | 最高分 | 阈值 |
|------|---------|--------|------|
| 知乎 | 专业性(4) + 可信度(3) + 热度(2) + 相关性(1) | 10 | ≥7 |
| 小红书 | 热度(5) + 种草价值(3) + 争议性(2) + 相关性(0) | 10 | ≥7 |
| 领英 | 商业价值(4) + 专业性(3) + 热度(2) + 相关性(1) | 10 | ≥7 |
| X (Twitter) | 影响力(4) + 相关性(3) + 时效性(2) + 传播度(1) | 10 | ≥7 |

**为什么权重不同**：
- **知乎**重视专业深度 → 专业性权重最高（4）
- **小红书**重视传播和种草 → 热度权重最高（5）
- **领英**重视商业价值 → 商业价值权重最高（4）
- **X**重视影响力 → 影响力权重最高（4）

**为什么是 10 分制**：
- 直观易懂（满分 10 分）
- 便于比较不同选题
- ≥7 分的阈值确保质量

**实现位置**：
- `.claude/skills/{platform}-filter/references/scoring-weights.md`

### 3. 手动备用方案

**设计**：Playwright 自动化发布失败时，提供手动指南

**实现**：
```markdown
## publish-base.md

### 自动化发布
尝试使用 Playwright 自动发布

### 降级方案
如果自动化失败，提供：
1. 手动操作指南（访问平台 URL，填写表单）
2. 剪贴板工具（自动复制内容到剪贴板）
3. APP 发布指引（打开 APP，粘贴内容）
```

**为什么这样设计**：
- 自动化依赖浏览器环境，可能失败
- 手动备用方案保证功能不中断
- "功能可用性" > "自动化程度"

**参考模式**：`.claude/knowledge/patterns/automation-fallback-pattern.md`

### 4. 本地资料整合

**设计**：支持 `assets/materials/` 和 `assets/analyzed/` 目录

**流程**：
```
1. 用户放置本地文件到 assets/materials/
2. create-base.md 检测本地文件
3. 如果有本地文件，跳过收集阶段或结合使用
4. 基于本地资料生成内容
```

**为什么这样设计**：
- 用户可能有现成的资料（PDF、网页、笔记）
- 本地资料更可靠，不受搜索质量影响
- 支持离线工作流程
- 本地资料和搜索结果可结合使用

## 4 轮搜索策略

### 轮次设计

| 轮次 | 搜索目标 | 关键词策略 | 输出 |
|------|---------|-----------|------|
| Round 1 | 广泛探索 | 主题相关的一般关键词 | 初步资料集合 |
| Round 2 | 深入挖掘 | Round 1 发现的子话题 | 细化资料 |
| Round 3 | 角度拓展 | 不同视角、观点、案例 | 多维资料 |
| Round 4 | 补充验证 | 数据、引用、权威来源 | 完整资料 |

### 为什么 4 轮？

- **太少（1-2轮）**：资料不够全面，容易遗漏重要角度
- **太多（5+轮）**：收益递减，时间成本高
- **4轮**：平衡了全面性和效率

### 实现位置

`.claude/skills/_shared/collect-base.md`

## Onboarding 系统

### 用户画像存储

**位置**：`.claude/skills/{platform}-create/references/user-profile.md`

**内容**：
```markdown
# 用户画像

## 基本信息
- 姓名/昵称
- 行业/领域
- 职位/角色

## 内容偏好
- 目标受众
- 语言风格
- 内容类型偏好

## 平台特性
- {平台特定配置}
```

### 为什么需要 Onboarding？

- **个性化内容**：不同用户需要不同风格
- **平台适配**：同一用户在不同平台的定位可能不同
- **一致性**：后续创作自动应用用户画像
