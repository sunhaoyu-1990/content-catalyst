## 基础问题

### Q1: 这个项目是做什么的？

**A**: 多平台内容创作辅助助手系统。帮助你在知乎、小红书、领英、X (Twitter) 四个平台上进行：
- 资料收集（4轮搜索）
- 选题筛选（10分评分）
- 内容创作（平台适配）
- 草稿发布（自动化+手动备用）

### Q2: 我需要会编程吗？

**A**: 不需要。所有功能通过命令和对话完成，无需编程知识。

### Q3: 支持哪些平台？

**A**:
- X (Twitter)
- 知乎
- 小红书
- 领英

**未来扩展**: 参考现有平台结构可添加新平台。

### Q4: workspace 和 talk_with_ai 的区别？

**A**: 简单回答：
- **workspace** = 你的"作品档案库"（存放创作产出）
- **talk_with_ai** = 我们的"聊天记录本"（存放对话记录）

详细对比：参见主文档中"两个文件夹的区别"部分。

## 模式选择

### Q5: 我该用极简模式还是完整模式？

**A**: 查看主文档开头的"模式选择决策表"。

**快速判断**：
- 第一次使用？→ **极简模式**
- 只想快速创作？→ **极简模式**
- 需要管理历史版本？→ **完整模式**
- 需要跨平台复用？→ **完整模式**

**重要**: 极简模式可以随时升级到完整模式。

### Q6: 如何从极简模式升级到完整模式？

**A**: 参见 @complete-mode-guide.md 中的"版本升级工作流"。

**简述**:
```bash
# 1. 重命名现有文件
mv workspace/ai-tools/content.md workspace/ai-tools/temp.md

# 2. 创建完整目录结构
mkdir -p workspace/ai-tools/v1/{00_collect,01_filter,02_create,03_publish}

# 3. 移动内容到对应位置
mv workspace/ai-tools/temp.md workspace/ai-tools/v1/02_create/final.md
```

### Q7: 完整模式太复杂，能简化吗？

**A**:
1. 从极简模式开始（只需 1 个文件）
2. 需要时再升级到完整模式
3. 完整模式的优势：历史回顾、跨平台复用、团队协作

## 目录结构

### Q8: 为什么要用日期和 v2/v3 混合命名？

**A**:
- **首次**: `{YYYY-MM-DD}` - 日期更直观
- **后续**: `v2`, `v3` - 明确表示版本序列

**示例**:
```
workspace/ai-tools/
├── 2026-01-27/    # 首次创作
├── v2/            # 第二次创作
└── v3/            # 第三次创作
```

### Q9: Windows 路径长度限制怎么办？

**A**:
1. 主题名称 ≤ 30 字符
2. 完整路径 ≤ 200 字符
3. 避免特殊字符

**详细方案**: 参见 @improvement-roadmap.md 中的 "Windows 路径检查清单"

### Q10: 必须创建所有这些目录吗？

**A**:
- **极简模式**: 只需 1 个 `content.md` 文件
- **完整模式**: 建议按规范创建，便于管理和导航

**创建技巧**: 使用脚本批量创建
```bash
mkdir -p workspace/{topic}/{version}/{00_collect,01_filter,02_create,03_publish}/{platform}
```

## 技能使用

### Q11: Collect 没找到资料怎么办？

**A**:
1. 更换搜索关键词
2. 使用本地资料（放到 `assets/materials/`）
3. 扩大搜索范围
4. 降低筛选标准

### Q12: Filter 筛选结果为空？

**A**:
1. 降低评分阈值（从 ≥7 改到 ≥6）
2. 调整评分权重
3. 手动指定选题
4. 检查搜索质量

### Q13: Create 生成的内容质量不佳？

**A**:
1. 检查用户画像配置
2. 提供更详细的选题说明
3. 手动指定内容类型
4. 基于本地资料创作

### Q14: Publish 自动化发布失败？

**A**: 使用手动备用方案
1. 参考技能中的手动操作指南
2. 使用剪贴板工具复制内容
3. 访问平台网站手动发布

**详细方案**: 参见 @technical-architecture.md 中的 "手动备用方案"

## 技术问题

### Q15: 文件编码有什么要求？

**A**: 所有文件使用 **UTF-8 without BOM** 编码。

**Windows 用户**: 确保编辑器保存为 UTF-8 without BOM
- VS Code: 右下角显示 "UTF-8"
- Notepad++: 编码 → 转为 UTF-8 无 BOM

### Q16: 索引文件必须维护吗？

**A**: 采用"最佳努力"维护策略：
- ✅ **必须**: 创建任务时添加条目
- ✅ **必须**: 完成任务时更新状态
- 🔄 **建议**: 每周整理一次
- ⏭️ **可选**: 修改任务内容时更新总结

**为什么不自动维护**: 参见主文档"索引维护说明"部分。

### Q17: 如何跨平台复用内容？

**A**: 参见 @complete-mode-guide.md 中的 "跨平台内容复用" 部分。

**简述**:
1. 先在一个平台创作（如知乎，专业详细）
2. 基于主版本，改编为其他平台
   - 领英: 提取商业洞察
   - 小红书: 简化为工具推荐，添加 emoji
   - X: 提炼核心观点，制作线程
3. 在 task.md 中记录内容关系

## 故障排除

### 问题: 创建目录失败

**可能原因**:
- Windows 路径过长（>260 字符）
- 包含特殊字符
- 权限不足

**解决方案**:
1. 缩短主题名称
2. 移除特殊字符
3. 检查目录权限
4. 以管理员身份运行

### 问题: 索引链接失效

**可能原因**:
- 路径变更
- 手动维护遗漏

**解决方案**:
1. 检查实际路径
2. 更新 index.md 中的链接
3. 定期验证索引准确性

### 问题: 技能执行失败

**可能原因**:
- 技能文件缺失
- 依赖文件未找到
- 参数错误

**解决方案**:
1. 检查 `.claude/skills/` 目录结构
2. 验证继承路径正确
3. 查看错误信息
