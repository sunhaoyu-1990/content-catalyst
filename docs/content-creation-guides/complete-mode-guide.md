# 完整模式使用指南

**用途**: 本文档提供完整模式的详细使用说明。完整模式通过**自然语言指令触发 Claude 自动化工作流**，无需手动创建目录结构。

## 完整模式 vs 极简模式

| 特性 | 极简模式 | 完整模式 |
|------|---------|---------|
| 触发方式 | 单个技能命令 | 自然语言指令 |
| 文件数量 | 1 个 | 多个（按阶段/平台） |
| 适用场景 | 单次创作、快速尝试 | 长期使用、版本管理 |
| 维护成本 | 低 | 中等（自动维护） |
| 功能覆盖 | 基础功能 | 全部功能（自动引导） |
| 升级难度 | - | 低（自动演进） |

**何时选择完整模式**：
- 需要回顾历史创作
- 需要跨平台复用内容
- 团队协作需要标准化
- 长期使用（计划创作 >10 篇）

## 如何开启完整模式

### 核心理念

完整模式不是让你手动创建目录，而是**通过自然语言告诉 Claude 你想做什么**，Claude 会自动：
1. 创建标准目录结构
2. 引导你完成各个阶段
3. 生成所有必要的输出文件

### 开启方法

**步骤 1：使用自然语言描述你的需求**

告诉 Claude 你想创作什么内容，使用完整模式：

```
示例对话：

用户: 我要用完整模式创作一篇关于"AI写作工具"的内容，发布到知乎和领英。

Claude: 明白了。我将启动完整模式工作流，为你创建标准目录结构并引导你完成各个阶段。
```

**关键触发词**：
- "完整模式"
- "使用完整工作流"
- "系统化创作"
- "标准化流程"

### Claude 的自动化响应

当检测到"完整模式"指令后，Claude 会自动执行以下操作：

#### 1. 确认主题和版本

```
Claude: 好的，我来为你创建完整模式项目。

请确认：
- 主题名称（如：AI写作工具）
- 版本标识（首次使用日期，如：2026-02-15）
```

#### 2. 创建标准目录结构

Claude 会自动创建以下目录：

```
workspace/
└── {主题名称}/
    └── {版本}/
        ├── 00_collect/     # 收集阶段输出
        ├── zhihu/
        ├── xiaohongshu/
        ├── linkedin/
        └── x/
        ├── 01_filter/       # 筛选阶段输出
        └── 02_create/       # 创作阶段输出
            ├── zhihu/
            ├── xiaohongshu/
            ├── linkedin/
            └── x/
        └── 03_publish/       # 发布阶段输出
            └── {平台}/

task.md                 # 任务追踪文件
```

#### 3. 自动执行完整工作流

Claude 会按顺序引导你完成每个阶段，并在每个阶段完成后自动进入下一阶段。

## 完整模式自动化工作流

完整模式遵循 **4 阶段自动化流程**：

```
┌─────────────────────────────────────────────────┐
│                                            │
│  阶段 1: 收集 (00_collect)                 │ ← Claude 自动调用 collect 技能
│    ↓                                       │
│  阶段 2: 筛选 (01_filter)                │ ← Claude 自动调用 filter 技能
│    ↓                                       │
│  阶段 3: 创作 (02_create)                 │ ← Claude 自动调用 create 技能
│    ↓                                       │
│  阶段 4: 发布 (03_publish)                │ ← Claude 自动调用 publish 技能
│                                            │
└─────────────────────────────────────────────────┘
```

### 各阶段的特点

#### 阶段 1：收集 (00_collect)

**触发方式**：`/zhihu-collect "主题"` 或 `/xiaohongshu-collect "主题"`

**Claude 会自动**：
- 执行 4 轮搜索策略
- 生成资料汇总文件
- 提示进入下一阶段

**输出文件**：
- `00_collect/materials.md` - 原始资料汇总
- `00_collect/references.md` - 参考链接列表

#### 阶段 2：筛选 (01_filter)

**触发方式**：`/zhihu-filter` 或 `/xiaohongshu-filter`

**Claude 会自动**：
- 根据平台评分标准评分
- 生成筛选结果
- 提示确认或修改选题

**输出文件**：
- `01_filter/selected.md` - 入选选题
- `01_filter/scored_topics.md` - 所有评分结果

**评分标准**（10 分制）：
- 知乎：专业性(4) + 可信度(3) + 热度(2) + 相关性(1)
- 小红书：热度(5) + 种草价值(3) + 争议性(2) + 相关性(0)
- 领英：商业价值(4) + 专业性(3) + 热度(2) + 相关性(1)
- X：影响力(4) + 相关性(3) + 时效性(2) + 传播度(1)

#### 阶段 3：创作 (02_create)

**触发方式**：`/zhihu-create "选题"` 或 `/xiaohongshu-create "选题"`

**Claude 会自动**：
- 加载平台 Profile 规范
- 整合收集的资料
- 根据平台要求创作内容
- 自动触发质量审查（checklist 规则）
- 自动触发图片标记（image-marking 规则）

**输出文件**：
- `02_create/{平台}/draft.md` - 初稿
- `02_create/{平台}/article.md` - 最终定稿
- `02_create/{平台}/meta.md` - 创作元数据（记录内容关系）

#### 阶段 4：发布 (03_publish)

**触发方式**：`/zhihu-publish` 或 `/xiaohongshu-publish`

**Claude 会自动**：
- 生成平台适配的发布指南
- 提供话题标签推荐
- 生成配图需求清单

**输出文件**：
- `03_publish/{平台}/guide.md` - 发布指南
- `03_publish/{平台}/checklist.md` - 发布前检查清单

---

## 各阶段输出说明

### 收集阶段输出

**位置**：`workspace/{主题}/{版本}/00_collect/`

| 文件 | 说明 |
|------|------|
| materials.md | 资料汇总，包含所有收集到的信息 |
| references.md | 参考链接列表，用于后续溯源 |

### 筛选阶段输出

**位置**：`workspace/{主题}/{版本}/01_filter/`

| 文件 | 说明 |
|------|------|
| selected.md | 最终选定的选题 |
| scored_topics.md | 所有候选选题的评分结果 |

### 创作阶段输出

**位置**：`workspace/{主题}/{版本}/02_create/{平台}/`

| 文件 | 说明 |
|------|------|
| draft.md | 初稿版本 |
| article.md | 最终定稿版本 |
| meta.md | 内容关系记录（用于跨平台复用） |

### 发布阶段输出

**位置**：`workspace/{主题}/{版本}/03_publish/{平台}/`

| 文件 | 说明 |
|------|------|
| guide.md | 发布指南，包含话题标签、最佳发布时间等 |
| checklist.md | 发布前检查清单 |

## 版本管理规则

### 自动版本命名

Claude 会根据以下规则自动命名版本：

| 场景 | 版本格式 | 示例 |
|------|---------|--------|
| 首次创作 | `{YYYY-MM-DD}` | `2026-02-15` |
| 后续创作 | `v2`, `v3`, `v4`... | `v2`, `v3` |
| 同一天多次 | `{YYYY-MM-DD}-a`, `{YYYY-MM-DD}-b` | `2026-02-15-a`, `2026-02-15-b` |

### 版本升级路径

```
v1 (首次)
  ↓ 优化/迭代
v2, v3, v4...
  ↓ 终极版本
```

## 任务追踪

### task.md 自动维护

完整模式会自动在 `workspace/{主题}/{版本}/task.md` 维护任务状态。

**文件位置**：`workspace/{主题}/{版本}/task.md`

**自动更新**：
- 创建目录时：初始化任务清单
- 进入各阶段时：更新对应任务状态
- 完成阶段时：标记为已完成

**任务状态**：
- `[ ]` - 待开始
- `[→]` - 进行中（Claude 正在执行此步骤）
- `[✓]` - 已完成

## 跨平台内容复用

完整模式支持**同一内容多平台适配**，通过 `02_create/meta.md` 记录内容关系。

### 内容关系记录

在创作阶段，Claude 会自动记录各平台内容之间的关系：

**示例 meta.md 内容**：

```markdown
## 内容关系

### 主版本
**平台**: 知乎
**类型**: 深度评测
**字数**: ~3000字

### 衍生内容

| 平台 | 关系类型 | 内容说明 |
|------|----------|----------|
| 小红书 | 基于主版本 | 简化为工具推荐笔记，突出核心功能 |
| 领英 | 基于主版本 | 提取商业洞察，适合职场人群 |
| X | 提炼观点 | 制作3条推文线程，引发讨论 |
```

### 使用方式

在创作时，Claude 会自动询问内容关系：

```
Claude: 正在为你创作知乎版本。这个内容是否需要生成其他平台的衍生版本？

用户: 是的，需要生成小红书版和领英版。

Claude: 好的，我会在创作完成后在 meta.md 中记录这些内容关系，供后续平台创作时参考。
```

## 常见问题

### Q: 如何在对话中开启完整模式？

**A**: 使用自然语言描述你的需求，包含以下关键元素：
- 主题名称
- 目标平台
- "完整模式"或"使用完整工作流"等触发词

**示例对话**：

```
用户: 我要用完整模式创作关于"AI写作工具"的内容，发布到知乎和领英。

Claude: 明白了。我将启动完整模式工作流，为你创建标准目录结构：
- workspace/ai-writing-tools/2026-02-15/
  ├── 00_collect/zhihu/
  ├── 00_collect/xiaohongshu/
  ├── 01_filter/zhihu/
  ├── 01_filter/xiaohongshu/
  ├── 02_create/zhihu/
  ├── 02_create/xiaohongshu/
  ├── 02_create/linkedin/
  ├── 03_publish/zhihu/
  ├── 03_publish/xiaohongshu/
  └── 03_publish/linkedin/
  └── task.md

首先，我会从收集阶段开始，逐步引导你完成所有阶段。
```

### Q: 必须手动创建目录吗？

**A**: 不需要。这就是完整模式的核心优势——通过自然语言指令，Claude 自动创建一切。

### Q: 可以中途调整计划吗？

**A**: 可以。随时告诉 Claude 调整计划，Claude 会相应更新任务状态和输出文件。

### Q: 如何添加新的平台支持？

**A**: 新平台支持已内置在系统中，只需：
1. 在 `.claude/profiles/` 创建平台配置文件
2. 使用时指定目标平台即可

### Q: 创作完成后如何继续？

**A**: 完整模式会自动检测当前阶段完成情况，并引导你进入下一阶段。无需手动干预。

### Q: 可以同时创作多个主题吗？

**A**: 可以。每个主题是独立的完整模式工作流，互不干扰。

### Q: 如何查看当前进度？

**A**: Claude 会自动在 `task.md` 中更新任务状态。你也可以随时询问"当前进度如何"。
