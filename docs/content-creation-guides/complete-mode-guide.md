## 完整模式 vs 极简模式

| 特性 | 极简模式 | 完整模式 |
|------|---------|---------|
| 文件数量 | 1 个 | 多个（按阶段/平台） |
| 适用场景 | 单次创作、快速尝试 | 长期使用、版本管理 |
| 维护成本 | 低 | 中等（需要维护索引） |
| 功能覆盖 | 基础功能 | 全部功能 |
| 升级难度 | - | 低（随时可升级） |

**何时选择完整模式**：
- 需要回顾历史创作
- 需要跨平台复用内容
- 团队协作需要标准化
- 长期使用（计划创作 >10 篇）

## 如何开启完整模式

完整模式通过**目录结构自动触发**。当你按照以下结构创建目录时，系统会自动识别并引导你完成整个流程：

### 方法 1：手动创建目录结构

```bash
# 创建主题目录
mkdir workspace/my-topic

# 创建版本目录（首次使用日期）
mkdir workspace/my-topic/2026-02-01

# 创建完整的4阶段目录
mkdir -p workspace/my-topic/2026-02-01/{00_collect,01_filter,02_create,03_publish}
```

**目录结构说明**：
- `00_collect/` - 资料收集阶段
- `01_filter/` - 选题筛选阶段
- `02_create/` - 内容创作阶段
- `03_publish/` - 发布准备阶段

**触发条件**：当检测到 `{主题}/{版本}/00_collect/` 目录存在时，自动触发完整模式流程。

### 方法 2：在现有目录中创建 task.md

如果你已经在某个目录工作，可以创建 `task.md` 来手动触发完整模式：

```markdown
# {主题名称} - {版本}

**创建日期**: 2026-02-01
**状态**: 进行中

## 流程步骤

1. [ ] 收集阶段 (00_collect)
2. [ ] 筛选阶段 (01_filter)
3. [ ] 创作阶段 (02_create)
4. [ ] 发布阶段 (03_publish)

## 涉及平台

- 知乎: https://zhihu.com/people/xxx/answers
- 小红书: https://xiaohongshu.com
```

**注意**：将 `task.md` 放在主题或版本目录的根目录下即可触发完整模式引导。

## 完整模式工作流程

完整模式遵循以下 **4 阶段流程**，每个阶段都有明确的输入和输出：

```
┌─────────────────────────────────────────────┐
│                                        │
│  1. 收集阶段 (00_collect)               │
│    ↓                                  │
│ 2. 筛选阶段 (01_filter)              │
│    ↓                                  │
│ 3. 创作阶段 (02_create)               │
│    ↓                                  │
│ 4. 发布阶段 (03_publish)               │
│                                        │
└─────────────────────────────────────────────┘
```

### 阶段 1：收集 (00_collect)

**目标**：为指定主题收集全面的背景资料

**使用命令**：
```bash
/zhihu-collect "你的主题"
/xiaohongshu-collect "你的主题"
```

**输出文件**：
- `00_collect/materials.md` - 原始资料汇总
- `00_collect/references.md` - 参考链接列表

**执行内容**：
- 4 轮搜索策略
  - 第 1 轮：核心关键词搜索
  - 第 2 轮：热门话题搜索
  - 第 3 轮：竞品文章分析
  - 第 4 轮：深度资料挖掘

### 阶段 2：筛选 (01_filter)

**目标**：从收集的资料中评分筛选最佳选题

**使用命令**：
```bash
/zhihu-filter
/xiaohongshu-filter
```

**输出文件**：
- `01_filter/selected.md` - 入选选题
- `01_filter/scored_topics.md` - 所有评分结果

**评分标准**（10 分制）：
- 知乎：专业性(4) + 可信度(3) + 热度(2) + 相关性(1)
- 小红书：热度(5) + 种草价值(3) + 争议性(2) + 相关性(0)
- 领英：商业价值(4) + 专业性(3) + 热度(2) + 相关性(1)
- X：影响力(4) + 相关性(3) + 时效性(2) + 传播度(1)

**通过阈值**：≥ 7 分

### 阶段 3：创作 (02_create)

**目标**：为入选的选题创作高质量内容

**使用命令**：
```bash
/zhihu-create "选题标题"
/xiaohongshu-create "选题标题"
```

**输出文件**：
- `02_create/{平台}/draft.md` - 初稿
- `02_create/{平台}/article.md` - 定稿
- `02_create/meta.md` - 创作元数据

**执行内容**：
1. 加载平台 Profile 规范
2. 整合收集的资料
3. 根据 Profile 要求创作内容
4. 自动触发质量审查
5. 自动触发图片标记

**平台支持**：
- `zhihu-create` - 知乎专业文章
- `xiaohongshu-create` - 小红书种草笔记
- `linkedin-create` - 领英商业文章
- `x-create` - X/Twitter 推文和线程

### 阶段 4：发布 (03_publish)

**目标**：生成发布指南，准备在各平台发布

**使用命令**：
```bash
/zhihu-publish
/xiaohongshu-publish
```

**输出文件**：
- `03_publish/{平台}/guide.md` - 发布指南
- `03_publish/checklist.md` - 发布前检查清单

**执行内容**：
1. 生成平台适配的发布建议
2. 提供话题标签推荐
3. 提供最佳发布时间建议
4. 生成配图需求清单

## 版本管理规则

### 首次创作

**版本格式**：`{YYYY-MM-DD}`

**示例**：
- `2026-02-01` - 2026 年 2 月 1 日首次创作

### 后续创作

**版本格式**：`v2`, `v3`, `v4` ...

**规则**：
- 递增版本号
- 每次迭代都是基于前一版本的改进

### 同一天多次创作

**版本格式**：`{YYYY-MM-DD}-a`, `{YYYY-MM-DD}-b`

**示例**：
- `2026-02-01-a` - 同一天第一次后续
- `2026-02-01-b` - 同一天第二次后续

每个版本目录下应包含 `task.md` 作为任务导航和进度跟踪文件。

### task.md 模板

```markdown

**创建日期**: 2026-02-01
**状态**: {进行中/已完成/已发布}

## 流程步骤

1. [ ] 收集阶段 (00_collect)
   - [ ] 完成 materials.md
   - [ ] 完成 references.md

2. [ ] 筛选阶段 (01_filter)
   - [ ] 完成评分
   - [ ] 确认入选选题

3. [ ] 创作阶段 (02_create)

   - [ ] 完成定稿 (article.md)

   - [ ] 完成各平台内容

- 知乎: https://zhihu.com/people/xxx/answers
- 小红书: https://xiaohongshu.com

## 跨平台内容复用

完整模式的一个核心优势是**内容复用**。

### 复用场景

**场景 1：同一内容，多平台发布**

```
收集阶段: 通用资料
    ↓
筛选阶段: 根据平台评分筛选
    ↓
创作阶段:
  - 知乎版: 专业深度文章
  - 小红书版: 种草推荐笔记
  - 领英版: 商业洞察文章
  - X 版: 核心观点推文
```

**内容关系记录**：

在 `02_create/meta.md` 中记录各平台内容之间的关系：

```markdown
## 内容关系

### 知乎

**主版本**: {描述}

**衍生内容**:
- 小红书: {基于知乎内容，简化为工具推荐}
- 领英: {提取商业洞察}
- X: {提炼核心观点}
```

### 使用方式

在创作阶段使用 `--relate` 参数指定关联内容：

```bash
# 创建关联到知乎内容的领英版本
/zhihu-create "商业洞察版" --relate=zhihu:2026-02-01

# 创建关联到知乎内容的小红书版本
/xiaohongshu-create "工具推荐版" --relate=zhihu:2026-02-01
```

## 常见问题

### Q: 如何切换从极简模式到完整模式？

**A**: 只需按照完整模式的目录结构创建目录和文件，系统会自动识别并引导你完成流程。不需要任何特殊配置。

### Q: 必须使用完整的 4 阶段结构吗？

**A**: 推荐使用，但可以灵活调整。例如：
- 如果不需要筛选阶段，可以直接从创作开始
- 如果只需要收集+创作，可以跳过发布阶段

### Q: 如何添加新的平台支持？

**A**:
1. 在 `.claude/profiles/` 创建新的平台配置文件
2. 在 `.claude/skills/` 创建对应平台的技能目录
3. 参考 `@platform-configs.md` 的格式和评分权重设置

### Q: 创作过程中可以切换平台吗？

**A**: 可以。在创作阶段使用不同的平台命令即可：
```bash
# 先创作知乎版本
/zhihu-create "我的选题"

# 再创作小红书版本（可以复用资料）
/xiaohongshu-create "我的选题" --relate=zhihu:2026-02-01
```

### Q: 如何批量创建多个主题？

**A**: 为每个主题创建独立的版本目录：
```
workspace/
├── topic1/2026-02-01/
├── topic2/2026-02-01/
└── topic3/2026-02-01/
```
