### 支持平台

| 平台 | 命令前缀 | 内容类型 | 风格特点 |
|------|---------|---------|---------|
| **知乎** | `zhihu-` | 专业回答、专栏文章 | 专业严肃、深度分析 |
| **领英** | `linkedin-` | 行业洞察、专业分享 | 职业化、商业视角 |
| **小红书** | `xiaohongshu-` | 种草笔记、测评分享 | 亲和力强、种草风格 |
| **X (Twitter)** | `x-` | Posts, Threads, Replies | 简洁有力、高传播 |

### 核心命令速查

```bash
# 资料收集
/{platform}-collect "主题"

# 选题筛选
/{platform}-filter

# 内容创作
/{platform}-create "选题"

# 发布准备
/{platform}-publish
```

<a name="workspace-vs-talk"></a>
## 📂 两个目录的区别

| 特性 | workspace/ | talk_with_ai/ |
|------|-----------|---------------|
| **用途** | 存放创作产出 | 存放对话记录 |
| **像什么** | 作品档案库 | 聊天记录本 |
| **内容举例** | 文章草稿、最终内容、发布状态 | 对话摘要、关键洞察、行动项 |
| **结构** | 4层：主题→版本→阶段→平台 | 2层：主题→版本 |

**简单记忆**：
- `workspace/` = 你的**作品**（对外发布的内容）
- `talk_with_ai/` = 我们的**对话**（交流的想法和计划）

<a name="modes"></a>
## 🎯 模式选择

两种模式都通过**自然语言对话触发**，Claude 会自动完成所有工作。

### 极简模式（推荐新手）

**适用场景**：
- 快速创作一篇内容
- 不需要版本管理
- 不需要跨平台复用

**使用方法**：直接用自然语言告诉 Claude 你的需求

```
示例对话：

用户: 帮我写一篇小红书种草笔记，主题是"AI写作工具推荐"

Claude: 好的，我来为你创作小红书种草笔记。
       [自动执行：创作 → 质量审查 → 图片标记]
       内容已保存到 workspace/ai-writing-tools/content.md
```

**自动化流程**：
```
自然语言需求 → 创作 → 自动审查 → 自动标记 → 完成
```

### 完整模式（推荐高级用户）

**适用场景**：
- 系统化管理多个内容
- 需要版本控制和历史追溯
- 需要跨平台内容复用

**使用方法**：用自然语言说明你要用"完整模式"

```
示例对话：

用户: 我要用完整模式创作关于"AI写作工具"的内容，发布到知乎和领英

Claude: 明白了，我将启动完整模式工作流：

       Step 1: 创建标准目录结构
       workspace/ai-writing-tools/2026-02-13/
       ├── 00_collect/zhihu/
       ├── 00_collect/linkedin/
       ├── 01_filter/
       ├── 02_create/zhihu/
       ├── 02_create/linkedin/
       └── 03_publish/

       Step 2: 收集资料（4轮搜索策略）
       [自动执行 collect 技能]

       Step 3: 筛选选题（10分评分系统）
       [自动执行 filter 技能]

       Step 4: 创作内容（按平台规范）
       [自动执行 create 技能 → 质量审查 → 图片标记]

       Step 5: 发布准备
       [自动执行 publish 技能]

       全部完成！内容已保存。
```

**自动化流程**：
```
自然语言 + "完整模式"
    ↓
自动创建目录结构
    ↓
自动收集资料
    ↓
自动筛选选题
    ↓
自动创作内容
    ↓
自动质量审查
    ↓
自动图片标记
    ↓
自动发布准备
    ↓
完成！
```

**目录结构（自动创建）**：
```
workspace/
├── index.md                # 主索引（自动更新）
└── {topic}/
    └── {version}/          # 自动命名：首次用日期，后续用v2,v3...
        ├── 00_collect/     # 收集阶段（自动生成）
        ├── 01_filter/      # 筛选阶段（自动生成）
        ├── 02_create/      # 创作阶段（自动生成）
        ├── 03_publish/     # 发布阶段（自动生成）
        └── task.md         # 任务追踪（自动维护）
```

**完整模式优势**：
- ✅ 自然语言触发，无需手动操作
- ✅ 全流程自动化（收集→筛选→创作→审查→标记→发布）
- ✅ 版本管理和历史追溯
- ✅ 跨平台内容复用
- ✅ 自动维护索引

<a name="platforms"></a>
## 📊 平台特色

### 知乎 - 专业深度

**特点**：专业严肃、深度分析
**评分权重**：专业性(4) + 可信度(3) + 热度(2) + 相关性(1)
**内容类型**：技术文章、专业回答、深度分析

### 领英 - 商业视角

**特点**：职业化、商业价值
**评分权重**：商业价值(4) + 专业性(3) + 热度(2) + 相关性(1)
**内容类型**：行业洞察、管理经验、ROI分析

### 小红书 - 种草分享

**特点**：亲和力强、种草风格
**评分权重**：热度(5) + 种草价值(3) + 争议性(2) + 相关性(0)
**内容类型**：种草笔记、测评分享、使用心得

### X/Twitter - 简洁有力

**特点**：简洁有力、高传播
**评分权重**：影响力(4) + 相关性(3) + 时效性(2) + 传播度(1)
**内容类型**：短推文、长线程、回复互动

<a name="faq"></a>
## ❓ 常见问题

### Q1: 如何开始第一次创作？

**A**: 最简单的方式：
```bash
/xiaohongshu-create "你想写的主题"
```

系统会自动完成创作、审查、图片标记。

### Q2: 创作内容保存在哪里？

**A**:
- 极简模式：`workspace/{topic}/content.md`
- 完整模式：`workspace/{topic}/{version}/02_create/{platform}/article.md`

### Q3: 如何查看历史创作？

**A**: 查看 `workspace/index.md` 主索引文件。

### Q4: 创作失败怎么办？

**A**:
1. 检查主题是否明确
2. 尝试提供更详细的说明
3. 查看错误日志了解原因

### Q5: 如何自定义用户画像？

**A**: 在 create 命令中添加 `--profile` 参数，或在对话中描述你的用户画像。

### Q6: 支持哪些平台？

**A**: 目前支持知乎、领英、小红书、X/Twitter。持续扩展中。

### Q7: 如何确保内容质量？

**A**:
- 系统自动触发质量审查（6个维度）
- 建议人工审核后再发布
- 可以使用 content-reviewer 技能进行深度审查

### Q8: 图片如何生成？

**A**:
- 系统自动添加图片标记（包含 Prompt）
- 将 Prompt 复制到 AI 绘图工具（如 Midjourney）
- 生成的图片插入文章即可
